# Answer blocked dialogs from Slack

Status: spec (2026-09-30). Replaces the "needs confirmation on PC" notice with Slack
controls that answer the dialog remotely.

## Decisions (user, 2026-09-30)

- Scope = everything: Claude permission prompts, AskUserQuestion (single, multi-select,
  multiple questions, free text), plan approval (ExitPlanMode), Claude folder-trust at
  startup, Codex command approval, plus a generic keypad fallback when parsing fails.
- "Always allow" / "don't ask again" options ARE shown as buttons (no filtering).
- D6 revised: a thread reply while the thread's agent is `blocked` is no longer rejected;
  it is used as the dialog's free-text answer (see §5).

## Spike facts (verified live on Herdr 0.8.2, Claude Code 2.1.285, Codex 0.159.0)

- Herdr reports `blocked` for: Claude permission, AskUserQuestion, plan approval, Claude
  folder-trust at startup (`agent start` → `agent_not_ready`), Codex command approval.
- Codex folder-trust at startup is reported `idle` (NOT blocked); `agent start` succeeds.
- `herdr agent send-keys <agent> <digit>` selects a numbered option immediately (Claude and
  Codex). No Enter needed.
- Multi-select: digits toggle `[ ]`/`[✔]`; `right` moves to the next question tab / the
  `✔ Submit` tab, which shows "Review your answers … ❯ 1. Submit answers  2. Cancel".
- Multiple questions: answering a single-select question with a digit auto-advances to the
  next question tab (`←  ☒ Color  ☐ Fruits  ✔ Submit  →`).
- Free text ("Type something." in AskUserQuestion, "Tell Claude what to change" in plan
  approval): press the option's digit (cursor moves onto it, it becomes an input), then
  `herdr pane send-text <pane_id> <text>` (Korean works), then `send-keys enter`.
- Unnumbered menus (Claude folder-trust: `❯ No, exit` / `Yes, I trust this folder`) need
  `down`/`up` then `enter`.
- Cursor marker: `❯` (Claude), `›` (Codex). Option text may wrap onto following indented
  lines; AskUserQuestion options have an indented description line under each label.
- Plan approval shows the plan file path in the footer
  (`ctrl+g to edit in Notepad · ~\.claude\plans\<slug>.md`) → full plan text can be read
  from that file (expand `~`).
- Right after sending keys the screen and the status lag (status stays `blocked` briefly).
  Never conclude from a single immediate read; poll.
- Codex only shows approval prompts when its config does not route them to
  `approvals_reviewer = "auto_review"` — document in README; not a bug.

## 1. Dialog parser — new module `herdr_slackbot/dialog.py` (pure, no I/O)

`parse_dialog(screen_text: str, agent_kind: str | None) -> Dialog | None`

- Work on the bottom region of the screen (below the last full-width `────` rule that
  precedes the dialog, or the last ~40 non-blank lines).
- `Dialog` fields (frozen dataclass): `kind` (`permission`, `question`, `question_review`,
  `plan`, `trust`, `codex_approval`, `unknown`), `title` (e.g. "Bash command", question
  header), `body` (lines: command/description/question text, plan excerpt), `question`
  (e.g. "Do you want to proceed?"), `options: tuple[Option, ...]`, `multi_select: bool`,
  `tabs` (question header tabs with answered state, if present), `plan_file: str | None`,
  `fingerprint: str`.
- `Option`: `number: int | None`, `label` (wrapped lines joined), `description`,
  `checked: bool | None` (multi-select), `free_text: bool` ("Type something",
  "Tell Claude what to change", Codex "No, and tell Codex what to do differently" is NOT
  free text — it is a plain option), `chat: bool` ("Chat about this"), `cursor: bool`.
- `fingerprint` = sha1 of the normalized dialog region with cursor markers removed
  (cursor movement alone must not change it); checkbox states and question text included.
- `unknown` kind: a dialog region was found but not classified — still return options if
  numbered lines exist; return `None` only when nothing dialog-like is found.
- `keys_for(dialog, option) -> list[str]`: numbered → `[str(number)]`; unnumbered → the
  `up`/`down` moves from the cursor option, then `enter`.

## 2. Slack message — `blocks.py`

Replace `blocked_blocks(name, ws_label)` with `dialog_blocks(name, ws_label, dialog, token)`:

- Header `⚠️ *<name>* · <ws> is waiting for your answer`, then title/body/question
  (body in a code block when it is a command; truncate with the existing 3000-char rule).
- Plan: plan text from `plan_file` if readable (else the screen excerpt), truncated, with
  the existing [전체 보기] mechanism for the full text.
- One button per option (label `"<n>. <label>"`, truncated to Slack's 75-char button text
  limit; full label stays in the section text). Multi-select: buttons show ☐/☑ and toggle;
  add `[Next →]` (sends `right`). Free-text option → button opens a modal with a multiline
  input (and the thread-reply path in §5). `Chat about this` → shown as a normal option.
- Always: `[Esc]` and `[Show screen]` (posts the last ~40 non-blank screen lines as a code
  block in the thread).
- `dialog is None` or `kind == unknown` with no options → keypad: `1`…`4`, `↑`, `↓`,
  `Enter`, `Esc`, plus the last ~15 screen lines as a code block.
- Button `value` stays small: `{"t": <token>, "o": <option index or key id>}`. The token
  refers to a pending-dialog record in state (§3) — do not put screen text in values.
- UI language: match existing bot strings (English), keep existing Korean button [전체 보기].

## 3. Bridge flow — `bridge.py`

- Where blocked is posted today (both the PC-notification path and the Slack-task path,
  `Action.BLOCKED`): read the screen (`visible` source), parse, store a pending-dialog
  record in `state` keyed by thread key: `{token, fingerprint, kind, options, message_ts,
  agent_session, pane_id, created_at}`, post `dialog_blocks`. Keep existing de-dup
  (`last_blocked_seq`, op ids) and mute behaviour.
- Slack-started agent blocked at startup (`agent_not_ready` in the new-agent flow): instead
  of "confirm it on PC", create/use the thread and post the dialog (trust screen) the same
  way; after it is answered and the agent becomes idle, continue with the original prompt
  if the new-agent flow had one (currently the prompt is dropped — keep the task so it is
  sent once the agent is idle; if this is too invasive, post "answered — use send" and say
  so in the progress notes).
- Codex started from Slack: after `agent start` returns idle, read the screen; if
  `parse_dialog` finds a `trust` dialog, treat it as blocked (post the dialog) before
  prompting.
- Button click handler (new actions registered in `slack_app.py`, behind the existing
  owner guard; do the work in the background like the other handlers):
  1. Load the pending record by token; missing/expired → reply "This question is no longer
     open." and strip the buttons.
  2. Fresh `agent.get` + screen read. Session changed / agent gone / not blocked /
     fingerprint differs → do NOT send keys; update the message to the current state
     ("Already answered or changed on PC", or re-render the new dialog).
  3. Send the keys (`agent.send_keys`; free text: digit, `pane.send_text`, `enter`).
  4. Poll (e.g. every 0.3 s up to ~5 s) until the fingerprint changes or the agent leaves
     `blocked`. New dialog still blocked (next question, review screen, re-planned plan,
     multi-select toggle) → edit the same message with the new dialog + new token. Agent no
     longer blocked → edit the message to `✅ <choice> — answered from Slack` without
     buttons and drop the pending record. No change after the timeout → keep buttons, post
     "⚠️ Could not confirm the answer; check the screen." with [Show screen].
  - Serialize answers per agent (a lock) so double clicks cannot send keys twice; the
    second click hits the fingerprint check.
- When the agent later leaves `blocked` for any other reason (answered on PC), the normal
  status handling should strip the buttons: edit the pending message to
  `✅ answered on PC` (or `ended`) and drop the record.
- Herdr client: add `send_keys(target, keys)` and `send_text(pane_id, text)` to
  `HerdrClient`; add CLI-transport mappings for `pane.send_text` (check the real socket
  method name/params with `herdr api schema`), keep `agent.send_keys` mapping.

## 5. Thread reply while blocked (D6 revised)

- `check_thread_target` currently rejects `blocked`. New behaviour for thread replies only
  (`/send` command and modal keep rejecting, with the §4 text):
  - current dialog has a `free_text` option → answer it with the reply text (same path as
    the free-text modal, including fingerprint check and polling);
  - otherwise → reply "This question needs one of the buttons above." (no keys sent).
