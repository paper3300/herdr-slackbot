| module | contents |

| `naming.py`, `agents.py` | name validation, `slack-<N>`, tab label, D5 option label (≤75), durations; claude/codex launch args (D4, D4-b). |
| `notify.py` | D6/D11 send gating, D8/D9 notification decisions, restart resume. |
| `__main__.py` | `python -m herdr_slackbot --check` (config + Herdr connectivity + agent list). |

## Herdr 0.8.2 findings (new since the spikes)
1. Socket read source is `recent_unwrapped` (underscore); the CLI spells it `recent-unwrapped`.
2. `agent read` with many lines while the agent is working/blocked fails with `agent_not_idle`. Read only after the agent settles.
3. **Transcript capture is unreliable.** A large `agent read` sometimes returns only the 50-line viewport, with `truncated: false`. For one pane it stayed viewport-only for every read, while other panes read fine. `read_agent()` retries (4×, 0.3s apart) and keeps the longest read; if the `●` block is missing, the parser falls back to the raw tail.
4. Herdr captures history by scrolling, so Claude's sticky header (a copy of the current `❯ prompt` line) is inserted mid-response. The parser drops these copies.
5. Status streams do not replay history. The lifecycle stream replays about 0.1s per event. You can subscribe to status for a pane before an agent starts in it.
6. `pane_updated` events carry `agent_session` and the title. `pane.agent_status_changed` carries neither, so the manager calls `agent.get` on each transition.
7. The codex prompt right after `agent start` returned `agent_prompt_stalled`, and the start of the prompt text was lost (Codex was still initializing). The prompt was only partly delivered.

This differs from D10 as written, so it needs a decision.

- **Mute vs blocked:** implemented as mute suppressing `blocked` for PC-originated work. A pending Slack task always notifies. Also, `blocked→done` counts as a completion for PC agents (D9 only names `working→done`).

## Review fixes (docs/review/M1.md)

| # | Fix | Tests |
|---|---|---|

A CLI timeout also counts as outcome unknown. | `test_herdr_client.py::test_review1_*` |
| 2 | Single state owner: status events are hints. Each one is re-checked with `agent.get`, and applied only if `state_change_seq` increased. Resync runs on the dispatcher (queued). | 3 | Per-pane session identity. | 4 | `pane.closed`, `pane.exited`, and the old side of `pane.moved` are verified with `agent.get` before anything is removed. If the lookup fails, the pane is kept and marked dirty. | `test_review4_*` (exited/closed/moved + failed lookup) |

## Recheck2 fixes (docs/review/M1-recheck2.md)

Approach: the live `agent.list` / `agent.get` state is treated as authoritative, with the periodic resync as the safety net, rather than adding more event-ordering special cases.

| # | Fix | Tests |
|---|---|---|
| N2 | A tracked agent is never reported `ended` on single-pane evidence. If found, the state is relocated there (`_adopt`: subscribe + reconcile, carrying working status/activity). If not found, the agent has ended. If the list call fails, the decision is parked (`_orphans`) and settled by the next resync, never ended on a guess.
